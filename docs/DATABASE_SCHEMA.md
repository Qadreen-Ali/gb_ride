# GB Ride — Database Schema

> Backend: **Supabase** (managed PostgreSQL)  
> All tables use UUID primary keys auto-generated by Supabase.  
> All timestamps are ISO 8601 strings.  
> Soft deletion via `is_deleted` boolean flag.

## 1. Entity Overview

```
┌──────────┐       ┌──────────────┐       ┌──────────────┐
│  locals  │  1:N  │    rides     │  N:1  │   drivers    │
│──────────│◄──────│──────────────│──────►│──────────────│
│ id (PK)  │       │ local_id(FK) │       │ id (PK)      │
│ auth_id  │       │ driver_id(FK)│       │ auth_id      │
└──────────┘       └──────┬───────┘       └──────────────┘
                          │ 1:N                    │ 1:N
                   ┌──────▼───────┐                │
                   │ ride_offers  │────────────────┘
                   │──────────────│
                   │ ride_id (FK) │
                   │ driver_id(FK)│
                   └──────────────┘
```

**Relationships:**
- A **Local** can have many **Rides** (one-to-many)
- A **Driver** can be assigned to many **Rides** (one-to-many)
- A **Ride** can have many **Ride Offers** (one-to-many)
- A **Driver** can send many **Ride Offers** (one-to-many)

## 2. Table: `locals`

Stores rider (local) profiles.

| Column | Type | Nullable | Default | Description |
|--------|------|----------|---------|-------------|
| `id` | UUID | No | `gen_random_uuid()` | Primary key |
| `auth_id` | UUID | No | — | Supabase Auth user ID (links to `auth.users.id`) |
| `phone_number` | TEXT | No | — | Phone number from OTP verification |
| `full_name` | TEXT | No | — | Full name |
| `cnic` | TEXT | No | — | National ID (CNIC) |
| `gender` | TEXT | No | — | Gender |
| `address` | TEXT | No | — | Home address |
| `current_lat` | FLOAT8 | Yes | `null` | Last known latitude (GPS) |
| `current_lng` | FLOAT8 | Yes | `null` | Last known longitude (GPS) |
| `is_deleted` | BOOLEAN | No | `false` | Soft delete flag |
| `created_at` | TIMESTAMPTZ | No | `now()` | Account creation timestamp |
| `updated_at` | TIMESTAMPTZ | Yes | `null` | Last GPS update timestamp |

## 4. Table: `rides`

Stores ride requests and their full lifecycle.

| Column | Type | Nullable | Default | Description |
|--------|------|----------|---------|-------------|
| `id` | UUID | No | `gen_random_uuid()` | Primary key |
| `local_id` | UUID | No | — | FK → `locals.id` (the rider) |
| `driver_id` | UUID | Yes | `null` | FK → `drivers.id` (assigned after offer accepted) |
| `pickup_location` | TEXT | No | — | Pickup address string |
| `destination_location` | TEXT | No | — | Destination address string |
| `pickup_lat` | FLOAT8 | No | — | Pickup latitude |
| `pickup_lng` | FLOAT8 | No | — | Pickup longitude |
| `dest_lat` | FLOAT8 | No | — | Destination latitude |
| `dest_lng` | FLOAT8 | No | — | Destination longitude |
| `distance_km` | FLOAT8 | No | — | Estimated distance in km |
| `eta_minutes` | INT4 | No | — | Estimated time in minutes |
| `fare` | FLOAT8 | No | — | Base fare (PKR), updated when offer accepted |
| `status` | TEXT | No | `'requested'` | Ride status (see enum below) |
| `driver_name` | TEXT | Yes | `null` | Denormalized driver name (set on accept) |
| `driver_image` | TEXT | Yes | `null` | Denormalized driver image URL |
| `driver_phone` | TEXT | Yes | `null` | Denormalized driver phone |
| `created_at` | TIMESTAMPTZ | No | `now()` | When ride was requested |
| `accepted_at` | TIMESTAMPTZ | Yes | `null` | When offer was accepted |
| `completed_at` | TIMESTAMPTZ | Yes | `null` | When ride was completed |

### Status Enum Values
| Value | Description |
|-------|-------------|
| `requested` | Local created ride, waiting for driver offers |
| `accepted` | Local accepted a driver's offer |
| `onWay` | Driver heading to pickup |
| `waiting` | Driver arrived at pickup, waiting for passenger |
| `ongoing` | Trip in progress |
| `completed` | Ride finished |
| `cancelled` | Cancelled by either party |

### SQL (Reference)
```sql

  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  local_id UUID NOT NULL REFERENCES locals(id),
  driver_id UUID REFERENCES drivers(id),

  pickup_lat FLOAT8 NOT NULL,
  pickup_lng FLOAT8 NOT NULL,
  dest_lat FLOAT8 NOT NULL,
  dest_lng FLOAT8 NOT NULL,
  distance_km FLOAT8 NOT NULL DEFAULT 0,
  eta_minutes INT4 NOT NULL DEFAULT 0,
  fare FLOAT8 NOT NULL DEFAULT 0,
  status TEXT NOT NULL DEFAULT 'requested',
  driver_name TEXT,
  driver_image TEXT,
  driver_phone TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  accepted_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ
);

-- Enable realtime
ALTER PUBLICATION supabase_realtime ADD TABLE rides;
```

## 6. Relationships Summary

```
auth.users (Supabase Auth)
  │
  ├──── locals.auth_id (1:1)
  │       │
  │       └──── rides.local_id (1:N)
  │               │
  │               └──── ride_offers.ride_id (1:N)
  │
  └──── drivers.auth_id (1:1)
          │
          ├──── rides.driver_id (1:N, nullable — set after offer accepted)
          │
          └──── ride_offers.driver_id (1:N)
```

### Key Relationship Rules
1. **`rides.local_id`** → references `locals.id` (NOT `auth_id`). This is the UUID from the `locals` table.
2. **`rides.driver_id`** → references `drivers.id` (NOT `auth_id`). NULL when ride is first created, set when an offer is accepted.
3. **`ride_offers.driver_id`** → references `drivers.id` (NOT `auth_id`). The driver's table UUID.
4. **`ride_offers.ride_id`** → references `rides.id`. CASCADE on delete.
5. To find the current user's driver record: `.eq('auth_id', supabase.auth.currentUser!.id)`
6. To find the current user's local record: `.eq('auth_id', supabase.auth.currentUser!.id)`

## 7. Denormalization Notes

Driver info is **denormalized** into both `rides` and `ride_offers` tables:
- `driver_name`, `driver_phone`, `driver_image` appear in `rides` (set on accept)
- `driver_name`, `driver_phone`, `driver_image`, `driver_rating`, `driver_total_rides` appear in `ride_offers`

**Reason**: Avoids JOIN queries on every real-time stream event. The Supabase real-time stream returns full row data, so having driver info inline means the UI can display it immediately without additional queries.

**Trade-off**: If a driver updates their name or image, old rides/offers retain the old data. Acceptable for MVP.

## 8. Row Level Security (RLS) — Recommended Policies

> **Status: Not yet implemented.** These are recommended policies to add.

### `locals` table
```sql
-- Locals can read/update their own row
CREATE POLICY "locals_own" ON locals
  FOR ALL USING (auth_id = auth.uid());
```

### `drivers` table
```sql
-- Drivers can read/update their own row
CREATE POLICY "drivers_own" ON drivers
  FOR ALL USING (auth_id = auth.uid());

-- All authenticated users can read online drivers (for nearby check)
CREATE POLICY "drivers_read_online" ON drivers
  FOR SELECT USING (is_online = true AND is_deleted = false);
```

### `rides` table
```sql
-- Locals can insert and read their own rides
CREATE POLICY "rides_local" ON rides
  FOR ALL USING (local_id IN (SELECT id FROM locals WHERE auth_id = auth.uid()));

-- Drivers can read requested rides and update assigned rides
CREATE POLICY "rides_driver_read" ON rides
  FOR SELECT USING (status = 'requested' OR driver_id IN (SELECT id FROM drivers WHERE auth_id = auth.uid()));

CREATE POLICY "rides_driver_update" ON rides
  FOR UPDATE USING (driver_id IN (SELECT id FROM drivers WHERE auth_id = auth.uid()));
```

### `ride_offers` table
```sql
-- Drivers can insert/read their own offers
CREATE POLICY "offers_driver" ON ride_offers
  FOR ALL USING (driver_id IN (SELECT id FROM drivers WHERE auth_id = auth.uid()));

-- Locals can read offers for their rides
CREATE POLICY "offers_local_read" ON ride_offers
  FOR SELECT USING (ride_id IN (SELECT id FROM rides WHERE local_id IN (SELECT id FROM locals WHERE auth_id = auth.uid())));
```

## 9. Supabase Realtime Configuration

For real-time streams to work, tables must be added to the `supabase_realtime` publication:

```sql
-- Run once in Supabase SQL Editor
ALTER PUBLICATION supabase_realtime ADD TABLE rides;
ALTER PUBLICATION supabase_realtime ADD TABLE ride_offers;
ALTER PUBLICATION supabase_realtime ADD TABLE drivers;
```

The app uses `.stream(primaryKey: ['id'])` which requires:
1. Table added to realtime publication
2. Table has a primary key column named `id`
3. RLS allows the authenticated user to read the rows
