🎯 KEY DESIGN DECISIONS
=========================

1. Two-tier Models
   - Canonical models (RideModel) map directly to Supabase schema
   - UI models (RideUiModel) have formatted display strings
   - Adapter pattern converts between them

2. Global Model Location
   - All models in lib/models/ for consistency
   - RideUiModel and RideAdapter moved from driver module to global
   - Both modules can now use same models

3. Service Layer Architecture
   - SupabaseService: Low-level DB operations
   - AuthService: High-level auth with both modules in mind
   - RideService: High-level ride operations for UI layers
   - Separation of concerns

4. Unified RideStatus
   - Single enum used globally
   - dbValue field for Supabase sync
   - displayName field for UI display
   - Helper methods (canStartRide, isActive, isFinal)
   - Includes "waiting" UI state that maps to "driverArrived" DB state

5. Error Handling
   - All services throw descriptive Exception messages
   - UI layers wrap calls in try-catch
   - User sees snackbar messages for errors

6. No State Management Framework (Yet)
   - Using setState for simple cases
   - Can upgrade to Provider/GetX when needed
   - Services are standalone and reusable
